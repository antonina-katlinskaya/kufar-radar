# Realt: перенос в GitHub — 26 октября 2026

## Применено

- Состояние Realt, архив наблюдений, подтверждения отправок и блокировки неопределённой доставки перенесены из D1 в отдельную ветку `realt-state`, файл `realt_state/state.json`. Сохраняются только ключи Realt. Предыдущие 6 подтверждений отправок импортированы; общие ключи Kufar и подписки не менялись.
- Realt читает Bir из отдельной ветки `realt-bir-snapshot`, файл `realt_state/bir.json`. После существующего успешного сканирования Bir выполняется один SELECT актуальных объектов и публикация компактного снимка. Повторный обход Bir не добавлен. В `bir-history/run.mjs` добавлен только вывод точного времени успешного сканирования в служебный файл; исходные запросы и правила сканирования не менялись.
- В самом процессе Realt нет D1-запросов и вызовов Workers. Его GitHub Actions не получают Cloudflare-секреты. Существующие Bir и Kufar продолжают использовать прежнюю инфраструктуру.
- Проверки появления нового снимка Realt запланированы каждые 10 минут в дневном окне: 90 коротких проверок в сутки. Архив обрабатывается один раз при восстановлении; затем только новые снимки. При неизменившемся снимке архив и Bir не перечитываются.
- Бир старше 35 минут не используется для новых ценовых уведомлений. При первичном восстановлении старого архива уведомления о ценах блокируются до свежего снимка Realt.
- Доставка жёстко ограничена подтверждённым личным Telegram владельца. Никакие списки подписчиков Kufar не используются. Отметка намерения отправки сохраняется до отправки, подтверждение — сразу после каждого сообщения. При неопределённом результате автоматический повтор блокируется; UUID остаются в диагностике.
- Исправлена совместимость истории дедупликации: числовые поля CSV и JSON и старая версия отпечатка без `material_edits` распознаются. На реальном перенесённом состоянии четыре прежних неизменившихся REVIEW исключены; пять новых/изменённых REVIEW и пять BACKDATED ожидают свежего источника.
- Поддерживаются отдельные состояния REVIEW/BACKDATED/RESOLVED. Для BACKDATED нужна неизменная дата публикации и возраст >24 часов. Этаж и адрес сами по себе предупреждение не вызывают. BYN не сравнивается с EUR. В карточках Bir используются прямые страницы объектов `/object/UUID/`.
- Полные результаты остаются в сжатом состоянии GitHub; Actions хранит только небольшую диагностику и квитанции 3 дня. Технические файлы в Telegram не отправляются.

## Только подготовлено: расписание сборщика

Изменения для `antonina-katlinskaya/realt-collector` подготовлены в файле [collector-github-migration.patch](https://github.com/antonina-katlinskaya/kufar-radar/blob/realt-private-test-20261026/realt_test/collector-github-migration.patch).

Применение заблокировано ответом GitHub HTTP 403 `Resource not accessible by integration`. Для этого репозитория нужен доступ установленного GitHub-подключения. Код сборщика на сервере пока НЕ изменён.

Подготовленная схема: 15 полных часовых сборов в 07:10–21:10 по Минску. После 24 часов и минимум 15 успешных измеренных сборов — до 30 сборов в 07:10–21:40, если последние 15 запусков успешны, каждый не дольше 20 минут, нет 403/429 и рабочий архив меньше 2 ГБ. При ошибках частота остаётся/возвращается к часовой. Есть единая блокировка параллельных запусков, ограниченные повторы, глобальная пауза после 403/429, фактическое время получения каждого объекта, защита от частичного снимка, сжатие новых raw-файлов и сохранение всех CSV-строк в дневных архивах. Watchdog использует то же расписание и 25 минут допуска. `collector.py`, `queries.py`, `config.py` не меняются.

Пока действует прежняя схема: пять номинальных дневных слотов через три часа и дополнительные проверки восстановления. За 20–25 октября фактически видны 3–4 вероятных полных сбора в сутки (по длительности), без ошибок/повторов. Проверенный полный запуск [40326081859](https://github.com/antonina-katlinskaya/realt-collector/actions/runs/40326081859): сбор `12:54:11–13:04:55Z`, 644 секунды. Часовой этап и получасовые сборы ещё не проверены в работе.

## Бесплатные ресурсы и ограничения

До переноса, 26 октября при замере: 4 058 157 чтений D1 по всему доступному аккаунту из 5 млн. Это частичный день, не прогноз. За 19–25 октября базовая нагрузка двух активных БД составляла примерно 2,94–3,36 млн чтений в сутки. Новый экспорт Bir добавляет около 125 088 чтений/сутки при 96 экспортированиях и 1 303 строках; 0 D1-записей и 0 новых вызовов Workers со стороны экспорта. Проверки Realt теперь не добавляют D1-нагрузку. Перечитывание архива на каждом тестовом push отключено.

Расчётный запас при прежней максимальной базовой нагрузке и новом экспорте — около 1,52 млн чтений/сутки (~30%). Это оценка, которую нужно подтвердить полным днём после переноса, а не измеренный остаток сегодняшнего дня. Будущий рост числа объектов и другие проекты могут изменить запас. Общий расход Workers и суммарное хранилище артефактов аккаунта GitHub полностью не измерены; перенос не означает подтверждение всех квот. Платные тарифы не включались.

Снимок Bir и состояние Realt хранятся в Git-ветках, не в удаляемом кэше Actions. Архив ограничен защитными порогами, но не обещает бесконечное хранение. GitHub cron может задерживать/пропускать запуски; жёсткую максимальную задержку уведомления гарантировать нельзя. Проверка нового снимка номинально занимает до 10 минут после его появления плюс очередь Actions и обработка; задержка самого обнаружения зависит от полноценных сборов.
