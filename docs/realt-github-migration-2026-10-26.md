## Как работает схема

1. `realt-collector` собирает анонимные данные в GitHub Actions. Исходные `collector.py`, `queries.py`, `config.py`, фильтры и паузы не менялись. Новая обёртка фиксирует фактическое время получения каждого объекта, проверяет целостность и публикует маркер полного снимка вместе с данными.
2. После существующего успешного обновления Bir формируется компактный снимок в ветке `realt-bir-snapshot`. Для него выполняется один SELECT текущих объектов, без записей в D1 и повторного обхода Bir.
3. Realt проверяет новый идентификатор снимка. В первый раз восстанавливает архив, затем читает только новые снимки. При повторной проверке того же снимка архив и сравнение с Bir не запускаются заново.
4. История наблюдений, отпечатки доставленных карточек и блокировки неопределённой доставки сохраняются в Git, а не в удаляемом кэше Actions. Намерение отправки записывается до вызова Telegram, подтверждение — после каждого сообщения. Неопределённая доставка автоматически не повторяется; UUID сохраняется в диагностике.
5. Realt имеет своё расписание проверок каждые 10 минут в дневном окне. Дополнительно он запускается после завершения существующего workflow `Radar`, даже если последний завершился ошибкой отправки Kufar. Новый процесс проверяет успешность именно шага обновления Bir. Код и правила Kufar для этого не изменялись; завершившийся workflow не ожидает Realt.

Прямое событие завершения сборщика между двумя репозиториями не настроено: оно требует отдельного межрепозиторного доступа во время выполнения. Использованы разрешённая в ТЗ проверка идентификатора снимка и независимый запуск наблюдателя после обновления источников. Очередь публикации объявлений и ноутбук в этой схеме не участвуют.

В вычислениях Realt и его состоянии D1/Workers больше не используются. Доступ Cloudflare передаётся только отдельному шагу экспорта существующего снимка Bir. Иногда нужен дополнительный точечный SELECT времени успешного сканирования по его ID; если время уже есть в журнале, этот запрос не выполняется. Уже экспортированный снимок пропускается до чтения таблицы объектов.

Последние 15 запусков должны быть успешными, каждый не дольше 20 минут, без 403/429; рабочие данные должны оставаться ниже 2 ГБ. При нарушении условий остаётся/возвращается часовой режим. Есть единая блокировка параллельных сборов, не больше двух попыток на слот и общая часовая пауза после 403/429. Watchdog использует тот же выбранный интервал и допуск 25 минут. ## Проверки логики

Совпадение: комнаты + точная площадь + специальная цена Bir при быстрой оплате. BYN не сравнивается с EUR. Ближайшая площадь — подсказка, не совпадение. Этаж и адрес вспомогательные.

BACKDATED требует изменения существенных параметров у объявления старше 24 часов при неизменной дате публикации. Старые по дате публикации и исчезнувшие объявления сохраняются. REVIEW, BACKDATED и RESOLVED различаются. Устранение расхождения проверено тестами; реальное устранение в сегодняшнем цикле не наблюдалось.
